- 2026-08-30 | Turned a one-paragraph idea ("a dashboard that shows where money is flowing") into a six-question page structure before writing any data code: is money growing, what does it cost, where is it sitting, where is it starting to move, what could move it next, who is positioned. Every panel had to answer one of the six or it was cut. | Shows the PM habit of forcing a product into questions the user actually asks, applied to a personal tool; the "no panel without a question" rule is a reusable framing for any dashboard. | [confidentiality-checked: personal project, public data sources only]
- 2026-08-30 | Chose the lean build: static HTML plus one nightly script and free data (FRED, yfinance, CFTC), no backend, no database, no paid feeds. Wrote down which paid sources were skipped and what proxies replace them. | A concrete "right-size to 8 to 10 hours a week" decision with the tradeoffs named, which is the kind of receipt build-in-public posts need. | [confidentiality-checked]
- 2026-08-30 | Reviewed the v0 dashboard the way a cross-asset desk would and rebuilt it: z-scores and percentiles instead of raw levels, bank reserves and the Treasury's bills mix instead of headline M2, term premium and financial conditions, an Investment Clock for regime, and the systematic flows (CTA flip levels, vol-control, dealer gamma) that actually move markets over days. Eight specific gaps, each fixed in the mock. | A concrete before-and-after of "amateur dashboard versus professional one" with the reasoning per gap; teaches without claiming authority because every gap is named and sourced to standard practice. | [confidentiality-checked: public methods, own project]
- 2026-08-30 | Ham reviewed the mock like a pull request and caught a chart flaw that had shipped: the grid line in every dot plot was painted over the data points (the grid was a CSS pseudo-element drawn after the dots), and every sparkline was one 100 by 38 drawing stretched to its tile, which distorted the lines. Fixed by moving the marks above the grid, drawing sparklines in pixel space with a faint range grid and a zero line, and adding axis ticks and trail markers to the rotation map and the Investment Clock. | An honest "review found something" receipt: three things professional charts get right (data above the grid, no non-uniform scaling, ticks on the axes) and how an AI-built page drifts from them without a human reviewer. | [confidentiality-checked: own project, public methods]
- 2026-08-30 | Ham asked to layer technical analysis ("charts and patterns from reputable sources") on top of the conditions ranking, on the logic that both agreeing makes growth very likely. Agreed with the goal, changed the method: named chart patterns have weak evidence and cannot be backtested, so the layer was built from five price rules with published evidence (200-day trend, 12-1 momentum, 50/200 state, 52-week high, breadth), scored beside the conditions score with a read column: aligned, conditions ahead, price ahead, divergence. Moved the trend pillar out of the conditions score so the two are independent. | A clean "agree with the goal, change the method" moment: why trend rules beat pattern reads, and why confluence raises hit rate but not expected return, since aligned trades are the crowded ones. | [confidentiality-checked: own project, public research]
- 2026-08-30 | Ham asked for a notification feature so a major change would flag the section as a must-read since his last visit. Designed it as a diff, not a feed: the nightly run logs state changes (never levels), the page shows the entries since each section was last read, with three tiers and a deliberate cap on the top one (a few must-reads a month, or the thresholds are wrong). Testing found a flaw on the first try: the regime block marked itself read three seconds after landing because it sits under the strip, so a must-read about the ranking would have cleared itself. Fixed by keying read-state to the link target, not the section. | The noise problem is the whole problem with alerts, and the fix is structural (state changes, last-read diff, a cap) rather than a smarter model; the self-clearing bug is a small honest receipt of testing what you build. | [confidentiality-checked: own project]
- 2026-08-30 | Ham flagged tile labels cut off with "..." ("where I can't read the rest of the text"). The fix was one rule: never truncate copy; wrap it with reserved height so the figures stay aligned. | A tiny example of a global design rule coming out of one review comment. | [confidentiality-checked]

- 2026-08-30 | v1 went live locally: a stdlib-only Python fetcher (no pandas, no yfinance, no API keys) pulls 113 series from FRED, Yahoo's chart endpoint and the ECB data portal in about two minutes and fills 542 readings on the page, each with its source and date. | The "boring stack" story: the plan said yfinance, the probe showed the raw endpoints were enough, and zero dependencies means the same script runs on a 2019 Mac and on a free GitHub runner. | [confidentiality-checked]
- 2026-08-30 | FRED timed out for every request from Python while curl answered in half a second. Not IPv6, not a ban: Akamai stalls a client that sends a browser-style User-Agent without a browser's fingerprint. The honest "MarketWatch/0.1" UA passed first time. | A debugging story with a clean moral: pretending to be a browser is what got blocked; identifying yourself is what worked. | [confidentiality-checked]
- 2026-08-30 | Reviewing the first real output like a PR: "Failed breakout" showed on ten of seventeen ranking rows. Cause: in a rising market every up day is a new 20-day high, so any dip counted as a failure. Keyed the tag to the 55-day level; the rule now fires where it should. Same pass caught rule B punishing Treasuries for lagging stocks, and a field-name collision that blanked every delta in the strip. | The rules read fine on paper; only live data showed where they were noisy. Ship, then read the output. | [confidentiality-checked]
- 2026-08-30 | Yahoo's free feed for ^VIX3M, CSI 300 and the SET stopped on 17 Jul. Rather than hide it, the page now greys any reading older than its refresh interval and prints the date, straight from the quant standard already written on the page ("show the timestamp; a stale panel greys out"). | Free data has gaps; the honest design is to show them. | [confidentiality-checked]
- 2026-08-30 | v1.1: eight more free feeds without a single API key. The trick was reading what institutions already publish as plain files: BIS policy rates as SDMX CSV, EIA's HTML history tables (its CSV downloads hide behind signed redirects), Cboe's index history CSVs, Treasury's FiscalData API, the BoJ's time-series HTML, the ICI's release page, the Cleveland Fed's 7 MB chart file. Standard library parsers, each with a unit test on a trimmed copy of the real page. | Shows the build-in-public method: probe first, keep only what a nightly job can read for free, test the parser so a layout change fails the test before it fails the page. | [confidentiality-checked]
- 2026-08-30 | Review moment: the first live output showed "Refilling: a floor bid under $65" in normal ink next to a live SPR reading of -123 mb year to date. The number was right, the sentence was draft copy from the layout. Fix: any narrative cell beside live numbers is now muted and tagged as draft until the v2 rules write it. | A concrete example of "every placeholder must be labelled": the dangerous placeholder is prose, not a number. | [confidentiality-checked]
- 2026-08-30 | Honest labels over impressive ones: "Global M2" became "Big-3 M2 in dollars" because China's M2 has no free monthly feed (the statistics bureau blocks non-browser clients and the mirror runs months behind). Same for uranium (Sprott physical trust as a labelled spot proxy) and the PBoC row (the BIS series is the one-year loan prime rate, so that is what the row says). | Small tradeoff worth sharing: a dashboard is only as trustworthy as its least honest label. | [confidentiality-checked]
- 2026-08-30 | v2 detector shipped with honest holes rather than fake completeness: of the five conditions, flows are "not scored" (no free share-count feed) and breadth is scored only where a free holdings file exists (the SPDR funds). The state machine still runs on what is real: relative strength on vol-adjusted returns, an eight-week seasonal window over twenty years, and a macro driver per theme. | A product lesson worth telling: when a rule has no data, show "not scored" in the row instead of quietly dropping the rule; the reader should see the shape of what is missing. | [confidentiality-checked]
- 2026-08-30 | The three-close rule as code: a state flips only after the raw state has held for three consecutive daily runs, a same-day rerun does not count as a second close, and the first run logs nothing because there is nothing to diff against. Alerts are a diff between yesterday's state file and today's, never a level. | Shows how a "no noise" notification promise becomes three small mechanisms; good build-in-public material about restraint. | [confidentiality-checked]
- 2026-08-30 | Review catch before the first run: the backtest looked up macro readings with a linear scan per day, which across sixteen themes and four thousand sessions would have run for tens of minutes every night. Replaced with a cached bisect view, minutes to seconds. | A concrete performance story from a stdlib-only build; relatable for anyone doing nightly jobs on free runners. | [confidentiality-checked]
- 2026-08-30 | v3: the positioning section went live from the CFTC's public API, a dark pool CSV, Cboe's per-day JSON, a survey page, a FINRA table and a crypto index, all free. The first honest result: the page's contrarian alert line (1.5) fired on four of nine markets on day one, and the three-year record says those crossings were followed by the opposite of what the rule expects in gold and crude. The log now exists to tune it; the page shows the record next to the alert instead of hiding it. | The build-in-public moment is the rule being tested against its own history in public, not the dashboard. | [confidentiality-checked]
- 2026-08-30 | Feeds that do not exist get a row that says so: fund manager cash, insiders, Google Trends, NAAIM and the OCC small-trader data are all "no free feed" on the page, and the averages simply skip them. Keeping the row instead of deleting it shows the reader the shape of the method versus the shape of the data. | Small design principle worth a post. | [confidentiality-checked]
- 2026-08-30 | v4: the event calendar went live without a single API key. The plan said Finnhub or FMP (both need keys); the probe found what institutions already publish: Forex Factory's public JSON for the week, the Fed's, ECB's and BoJ's own meeting pages, the BLS release archives (every payrolls and CPI release since 2008, plus the pre-registered schedule), TreasuryDirect's auction list and the Cboe SPX chain. Rules fill the rest and say "usual slot, to confirm" until a feed confirms them. | The "read what is already published" method again, with a twist worth telling: the honest calendar has two kinds of rows, confirmed and guessed, and the page shows which is which. | [confidentiality-checked]
- 2026-08-30 | Options-implied move per event, from first principles: the SPX chain has an expiry every trading day, so the variance between two consecutive expiries is the variance of one session. The session carrying payrolls prices ±0.8%, the September FOMC ±1.0%, a normal session ±0.6%. That number is now the bar for calling a reaction big, next to the median move on the last 187 payroll days (0.6%). | A small, teachable piece of options math that turns "the market expects a big day" into a measured figure; good build-in-public material because it can be checked. | [confidentiality-checked]
- 2026-08-30 | Review catch on a rule: the payroll release rule (three Fridays after the reference week) was checked against 143 actual BLS dates. Thirteen misses, in two families: the BLS publishes on Good Friday even though the stock market is closed, and January reports slip a week from the New Year. Fixed both; the only misses left are the 2025 shutdown delays. | A rule is a hypothesis until you test it against the archive; the archive was free. | [confidentiality-checked]
- 2026-08-30 | The Sunday brief as a workflow, not an automation: the page carries rule-based Expect, Stronger and Weaker columns on every row (consensus, the event study, the options bar, positioning), and a twenty-minute Claude session on Sunday replaces them with a reviewed brief saved to a JSON file the nightly run merges. Rows say whether they are rule-based or reviewed, with the date. | The tradeoff worth sharing: the interpretive layer stays human-reviewed on purpose, while everything measurable is automated. | [confidentiality-checked]
- 2026-08-30 | The review before the visual pass measured the page instead of eyeballing it: a script listed every table wider than its card (eight, clipping their READ column by 19 to 257 px behind macOS overlay scrollbars) and the phone layout showed only the first column of the tables that carry the reads. The important points were on the page and invisible. Fix: wrap, fade with a hint, and cards under 640 px. | Good build-in-public material: the defect was invisible on the author's machine and only a measurement found it. | [confidentiality-checked]
- 2026-08-30 | Rule for the new visuals: every encoding draws a threshold the page already states, never a new one. The z dots shade beyond 2 because the copy says beyond 2 is stretched; the percentile bullets shade 20 and 80 because the sentiment rule says extremes are contrarian; the breadth bars carry the 35 and 60 marks because the thrust rule uses them. The ranking became a map with the five read zones shaded, so the read chip is visible as a place, not a word. | A design principle worth a post: charts should make the method visible, not add a second method. | [confidentiality-checked]
- 2026-08-30 | Tooling catch: the screenshot tool kept timing out on "waiting for element to be stable", and the project note blamed the tab. - 2026-08-31 | Ham asked for a snapshot-to-watchlist feature so the dashboard would surface assets that are cheap and growing exponentially. The premise got an honest correction before any code: this page cannot pick single cheap compounders (single names are out of scope by design), but its Conditions ahead read is precisely "improving conditions the price has not caught up to", so the feature became an evidence log instead: snapshot a ranked market as it stands, and every nightly run grades that call against the S&P 500 (early, working, stalled, not working, all on thresholds the page already states). The write path on a static page with no backend: a + link opens a prefilled GitHub issue, and an owner-guarded Action turns the issue into a commit. | Two reusable moves: reframing a feature request into its falsifiable version (grade the dashboard's own calls rather than promise stock picks), and issue-ops as a free write path for static sites. | [confidentiality-checked: own project, public data]
